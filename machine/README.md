# 机器码实验：图形界面引导

本目录与上一版原型分开，用于重新开始制作。`gui-bootstrap.hex` 直接记录手写的十六进制文件字节；它没有通过汇编器或高级语言编译器生成。文件包含 PE 头、x86-64 指令、Windows 导入表和文本。

Windows 自带的 `certutil` 可以把这些字节转换为可执行文件：

```text
certutil -f -decodehex machine\gui-bootstrap.hex machine\gui-bootstrap.exe 4
```

该可执行文件验证双语界面。首个窗口使用 Windows 的“是／否／取消”按钮。“是”进入中文提示，“否”进入英文提示，取消或按 Esc 直接退出。默认选中“取消”。目前只检查了 PE 结构和分支地址，尚未实际操作窗口。安装文件和配置 PATH 的功能待实现。

| 文件偏移 | 内容 |
| --- | --- |
| `0x0000` | DOS 头；`0x003c` 指向 PE 头。 |
| `0x0080` | x86-64 PE 头，子系统为 Windows GUI。 |
| `0x0200` | 入口指令：调用 `MessageBoxW`、根据结果选择中文或英文消息，再调用 `ExitProcess`。 |
| `0x0400` | Windows 函数导入表和 UTF-16 文本。 |

下一步仍需要验证此入口、实现真正的图形化安装流程、重新制作语言执行器及命令行入口，并完成端到端测试。上一版 `cc.exe` 和 `CircleSetup.exe` 仍属于不符合严格构建要求的旧原型，不能作为本次重做的最终结果。

新版本使用 `.cir` 扩展名。手写的 `circle.hex` 已实现命令行入口，可用以下命令转换并运行：

```text
certutil -f -decodehex machine\circle.hex machine\circle.exe 4
.\machine\circle.exe help
.\machine\circle.exe --help
.\machine\circle.exe version
.\machine\circle.exe build examples\add.cir -o add.exe
.\add.exe
$LASTEXITCODE
```

已实测无参数时显示帮助，未知命令返回退出码 1。`circle run 文件.cir` 按 1 KiB 分块读取。当前接受十进制整数和以 `+` 连接的整数表达式，将结果作为进程退出码。操作数和结果的有效范围为 `0` 至 `4294967295`，符号两侧可有 ASCII 空白。空文件或纯空白返回 0。缺少操作数、超出范围及其他语法以 `行:列: Invalid source` 报告。位置从 1 开始，列按源码字节计数，指向检测到问题的字节或文件末尾。文件打开或读取失败报告 `Cannot open.`。两种错误均返回 1，并向标准错误输出消息。运行 `examples\add.cir` 后，PowerShell 的 `$LASTEXITCODE` 为 42。开发顺序与验收标准见 [ROADMAP.md](../ROADMAP.md)。

`circle run` 和 `circle build` 都支持在表达式末尾加 `!`。出现该标记时，程序以十进制加换行写入标准输出，成功时返回退出码 0。示例 `examples\print.cir` 输出 `42`。省略标记时，表达式结果仍作为进程退出码。

最后一个操作数可写为 `?`。例如，在 PowerShell 中运行 `'5' | .\machine\circle.exe run examples\input.cir`，会输出 `24`。直接运行和编译产物都在执行时从标准输入取一个 ASCII 数字 `0` 至 `9`。输入为空、首字节不是数字、读取失败或结果超出 `0` 至 `4294967295` 时返回 2。此版本只读取首字节。

源码可以在最终表达式前声明多个局部整数。例如 `left: u8 = 19; limit = 23; left + limit!` 输出 `42`。显式类型 `u8` 的初值范围是 `0` 至 `255`，`u16` 的初值范围是 `0` 至 `65535`，`u32` 的初值范围是 `0` 至 `4294967295`。省略类型时按 `u8` 检查。初值须为十进制字面量。加法使用 `u32` 范围。名称由 1 至 8 个 ASCII 小写字母组成，每个程序最多声明 26 个变量。未知类型、未声明的引用和重复声明会报错。编译器在编译时解析变量引用。

可以在最终表达式前用 `set 名称 = 表达式;` 更新已声明的局部变量。赋值按出现顺序求值，右边支持字面量、局部变量和加法。赋值结果必须符合目标变量声明时的类型。`set` 是保留字。当前编译器在生成 EXE 前求值，赋值右边暂不支持运行期输入或控制流。

最终表达式可以写成 `条件 ? 非零分支 : 零分支`。分支可使用整数字面量、局部变量和加法，两支都会检查语法和溢出。末尾的 `!` 输出选中的结果。常量条件在编译时选支，条件写作 `?` 时在运行期读取一个 ASCII 数字。例如 `? ? 42 : 7!` 输入 `0` 输出 `7`，输入其他数字输出 `42`。每份源码支持一个条件表达式，分支内部暂不支持嵌套条件或输入。

计数循环写作 `次数 {步长}`。它从 0 开始，在运行期把步长累加指定次数。`6 {7}!` 输出 `42`，零次循环输出 `0`。次数和步长可以引用局部整数或使用加法。最多循环 65535 次，累加结果超出 `u32` 范围会在执行或生成 EXE 前报错。目前循环体只包含一个固定步长表达式。

`circle build 源文件.cir -o 输出.exe` 生成 1.5 KiB 的 Windows x64 程序。编译器将除最后一个操作数外的各项合为一个部分和。生成的程序先检查 `%LOCALAPPDATA%\Circle\circle.exe` 是否存在且为文件，失败时立即以 126 退出，再根据源码完成求和、读取输入、选支或计数循环，并输出结果或以结果退出。安装检查限于文件路径，尚未校验身份、签名或版本。输出文件已存在时返回 `Cannot write output.`。编译器内嵌 [exit-template.hex](exit-template.hex) 的 PE 字节，生成时写入文件偏移 `0x0281` 和 `0x0287` 的操作数、偏移 `0x0298` 的模式标记，以及偏移 `0x029c` 的运行期非零分支结果或循环次数。双语安装器仍待实现，测试使用工作区内的模拟安装目录。
